6) Security checks (live, this session)

$ curl -s http://127.0.0.1:8399/health
{"status":"ok","version":"0.2.0","upstream":"api.typesafe.ai","hasEnvKey":true}

$ curl -s -o /dev/null -w "%{http_code}" -H "Host: evil.example.com" http://127.0.0.1:8399/health
403   # forged Host rejected (expected)
$ curl -s -o /dev/null -w "%{http_code}" -H "Origin: https://evil.example.com" \
    -X POST http://127.0.0.1:8399/v1/chat/completions -H "Content-Type: application/json" \
    -d '{"messages":[{"role":"user","content":"x"}]}'
403   # browser origin rejected (expected)
$ curl -s -o /dev/null -w "%{http_code}" -H "Host: 127.0.0.1:8399" http://127.0.0.1:8399/health
200

loopback-only The bridge binds to 127.0.0.1, rejects forged Host headers and non-allow-listed browser Origins, and never forwards client tokens upstream unless they are real TypeSafe keys.

npm test

node typesafe-bridge/audit.cjs path/to/file.js
